# Citiverse demo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A separate, guided, GPS-free two-stop demo of Citiverse that anyone plays on their phone from one link.

**Architecture:** A copy of the game (commit 855866f) in a new repo, stripped of GPS, test mode, AI and replay. A pure state module (`js/demo/flow.js`) owns the step order, spawn, unlocks and saved progress; a driver (`js/demo/demo.js`) runs the steps against the existing map, stop panel, sheets and an extended practice-round guide that shows a talking Buddy. Locks are one attribute (`data-locked`) plus one capture-phase click blocker.

**Tech Stack:** Plain HTML/CSS/JS ES modules, no build; MapLibre GL 4.7.1 + deck.gl as in the game; `node --test` for pure modules; a Node CDP script driving headless Chrome for end-to-end tests; GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-11-27-demo-design.md` (copied into the demo repo in Task 1).

- New repo `Justin4625/Citiverse-demo`, public, branch `main`, GitHub Pages from `main` root; live at `https://justin4625.github.io/Citiverse-demo/`. Local folder: `~/Downloads/Minor DA/Groep D/AI/Prototype/citiverse-demo`.

## Review Focus

1. Fast double taps on a stop while the camera dives: exactly one stop panel opens and the step advances once (test in Task 6).
2. Closing the stop panel (X) in the middle of a minigame: the step stays, the stop stays unlocked and tappable, no stamp (test in Task 6).
3. Refresh during any step, incl. the walk: resumes per the spec, no double stamp or XP (test in Task 7).
4. Router offline or failing: route falls back to a straight line and the walk still arrives (test in Task 6, router blocked).
5. Read-aloud still playing when its bubble or screen goes away: it stops (test in Task 8).

### Task 2: Demo state (pure)

**Files:**
- Create: `js/demo/flow.js`, `tests/flow.test.mjs`

**Interfaces:**
- Produces (all pure; `storage` is any `{ getItem, setItem, removeItem }`, may throw):
  - `STEPS = ['notice', 'intro', 'rotate', 'zoomIn', 'zoomOut', 'stop1', 'profile', 'go', 'route', 'walk', 'stop2', 'end']`
  - `newDemo(locations, rand = Math.random) -> { step: 'notice', spawnId, nextId, stamps: {}, xpCounted: {} }` — `spawnId` uniform over `locations`, `nextId` = straight-line nearest other stop to the spawn (`distanceM` from `js/geo.js`).
  - `advance(state, from) -> state` — moves to the step after `from` only if `state.step === from` (idempotent; a second call is a no-op).
  - `isUnlocked(state, control) -> boolean` for controls `'gestures'`, `'settings'`, `'profile'`, `'go'`, `` `stop:${id}` ``, `` `route:${id}` ``. Table: gestures from `rotate`; settings always; `stop:${spawnId}` in `stop1`; profile from `profile`; go from `go`; `route:${nextId}` in `route`; `stop:${nextId}` in `stop2`. Everything else false.
  - `collectOnce(state, id, xp) -> { state, added: boolean }` — records stamp + XP once per stop id.
  - `walkMs(metres) -> number` = `Math.min(metres / 1.4 * 1000, 20000)`, never below 3000.
  - `save(state, storage)`, `load(storage) -> state | null` (key `citiverse-demo.flow.v1`; returns null on bad JSON or throwing storage). On load, a saved `walk` step comes back as `stop2` (Twinny placed at stop 2).
  - `reset(storage)`.
